# FlowEdge Mobile — Expo app with subscription entitlements

React Native + Expo app in [`mobile/`](../mobile). Same product philosophy as the web desk —
disciplined trade plans, exact levels, journaling, analytics — packaged as a subscription
mobile app with Free / Pro / Elite tiers.

## Architecture

```
mobile/
  app/                     Expo Router
    _layout.tsx            providers (React Query, Entitlements) + stack
    index.tsx              entry gate → onboarding or tabs
    onboarding.tsx         7-step flow (welcome → focus → pairs → sessions →
                           notifications → account → subscription offer)
    sign-in.tsx            Supabase email/password + magic link (guest in mock mode)
    (tabs)/                Home · Signals · Journal · Analytics · Profile
    signal/[id].tsx        trade plan detail (Pro reasoning, Elite derivations)
    paywall.tsx            modal — pricing cards, comparison, trial, restore
    billing.tsx            plan state, manage/restore, upgrade, FAQ
  src/
    entitlements/          plan/status model, central gating rules, context provider
    billing/               BillingProvider abstraction: RevenueCat adapter (native
                           builds) + Mock adapter (Expo Go/dev), product catalog
    api/                   typed client → web /api/scan, bundled real-engine samples
    hooks/                 useSignals, useJournal (Supabase or local fallback)
    analytics/             typed event tracker → Supabase telemetry tables
    notifications/         Expo push registration + tier rules
    lib/                   zod env, Supabase client (SecureStore sessions), prefs
    components/            ui primitives + SignalCard with locked-level states
  supabase/schema.sql      tables + RLS (see below)
```

Everything runs with **zero configuration** in Expo Go: mock billing (simulated purchases and
trials), bundled signals generated by the real engine, local journal. Adding env keys turns on
each real integration independently.

## Entitlement model

`plan ∈ {free, pro, elite}` × `status ∈ {none, active, trialing, grace, cancelled, expired}`.
A user is entitled while `active | trialing | grace`, and after cancelling until
`current_period_end`. All gating goes through `src/entitlements/gating.ts`:

| Gate | Free | Pro | Elite |
|---|---|---|---|
| Full signals / exact levels | 1 per day (top-confidence), rest masked | ✓ | ✓ |
| Reasoning | — | plain-English | + confidence equation & level derivations |
| Journal | 10 rows | unlimited | unlimited |
| Analytics | 7-day teaser | standard | + edge reports, setup×session, spread drag |
| Alerts | — | approved signals | custom |

## RevenueCat plan

- **Products**: `flowedge_pro_monthly` ($29.99), `flowedge_pro_yearly` ($239.99, save 33%,
  7-day trial on Pro), `flowedge_elite_monthly` ($59.99), `flowedge_elite_yearly` ($479.99).
- **Entitlements**: `pro` (granted by Pro products), `elite` (granted by Elite products, which
  also grant `pro`). Mapping in `src/billing/products.ts`.
- **App user id** = Supabase auth uid (`Purchases.logIn(uid)` on login) so webhook events land
  on the right row.
- **Purchase flow**: paywall → `purchase(productId)` → customer info → entitlement context
  refresh (also refreshed on every app foreground and login). Restore is one tap on the
  paywall and billing screens.
- **Webhook sync**: RevenueCat → `POST /api/webhooks/revenuecat` on the Next.js backend
  (Authorization header = `REVENUECAT_WEBHOOK_AUTH`). Handles INITIAL_PURCHASE, RENEWAL,
  PRODUCT_CHANGE, CANCELLATION, UNCANCELLATION, BILLING_ISSUE (→ grace), EXPIRATION, TRANSFER;
  upserts `entitlements` via the Supabase service role. Server-side gating (the `signals` RLS
  policy) reads this table — client checks are UX, the database is the enforcement.
- **Stripe**: intentionally not in the native app (App Store rules). The `BillingProvider`
  interface is the seam: a future web checkout writes to the same `entitlements` table and the
  app picks it up without changes.

## Supabase schema

`mobile/supabase/schema.sql`: profiles, subscriptions (raw store state), entitlements
(resolved plan — what everything gates on), signals + signal_views, journal_entries,
analytics_snapshots, notification_preferences, paywall_impressions, upgrade_events. RLS:
own-row access everywhere; approved-signal payloads readable only with an entitled row;
subscription/entitlement/signal writes are service-role only.

## Analytics events

`onboarding_step/completed · signal_detail_open · locked_feature_tapped(feature) ·
paywall_viewed(source) · upgrade_clicked · trial_started · subscription_purchased/restored ·
subscription_cancel_intent · churn_risk · feature_used` — typed union in
`src/analytics/track.ts`, stored in the telemetry tables (console in dev).

## Push notifications

`src/notifications/push.ts` registers an Expo push token into
`notification_preferences` with tier defaults (free: promotions; pro+: signal alerts). Sending
is server-side (Supabase edge function or the Next backend hitting Expo's push API on new
approved signals / trial ending / expiring subscription / optional daily recap), with tier
rules enforced from the `entitlements` table at send time.

## Setup

```bash
cd mobile
npm install
npm run typecheck
npm start               # Expo Go — full mock mode
```

Real integrations: copy `.env.example` → `.env`, fill Supabase URL/anon key (run
`supabase/schema.sql` first), `EXPO_PUBLIC_FLOWEDGE_API_URL` for live signals, RevenueCat
public keys, then build a dev client (`npx expo run:ios|android`) and
`npm install react-native-purchases` — the adapter loads it only outside Expo Go.

## Verification status

The TypeScript program compiles clean (`npm run typecheck`, strict mode). This environment has
no iOS/Android simulator, so screens were not exercised on-device — run `npm start` locally
for that. Store products, RevenueCat config, and the Supabase project are external setup.
